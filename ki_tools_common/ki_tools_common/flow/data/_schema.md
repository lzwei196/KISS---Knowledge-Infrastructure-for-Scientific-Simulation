# `obtain_map` schema — documents the structure produced by `derive_plan.py`

> **Important: this is NOT a config language for hand-written files.**
>
> An obtain map is the runtime output of `ata-kdt/planner/derive_plan.py` —
> auto-generated by joining each model's ATA card inputs against
> `forcing_providers/`, `data_ki/<X>/card.yaml`, and the coupling matrix.
>
> Do not write hand-written `obtain_map.yaml` files — extend `derive_plan.py`
> instead. The 5 demonstrational fixtures that used to live in `_examples/`
> have been removed; this schema doc is the canonical reference.
>
> This document defines the **shape** of what `derive_plan.py` produces, so
> downstream consumers (the agent, basin_context.yaml writer) can rely on the
> structure. It also serves as a reference for the strategy taxonomy used
> internally by `derive_plan.py`.

The card (`ata-kdt/cards/<MODEL>_ata_card.yaml`) says **WHAT** the model needs
(canonical IDs, units, valid ranges, traps). An obtain map says **HOW** to get
each of those when the user is silent.

## Strategy taxonomy

```yaml
strategy: <one-of>
```

| Strategy | When to use | Resolved by |
|---|---|---|
| `from_user` | User must provide; no sensible default | planner asks (in batched question) |
| `from_user_message.<kind>` | Typed extraction from user's free-text prompt (place_name, coords, year_range, station_id, crop, event) | typed regex/heuristic extractor — same dotted form is reused in `args:` |
| `from_forcing_provider` | Met variables (precip, temp, ...) | provider picked by `provider_pick.rule` |
| `from_dataset_lookup` | Static spatial data (soil, landcover, etc.) | agent reads `data_ki/<X>/SKILL.md` and accesses the file at `obs_datasets.path` |
| `from_constant_table` | Static reference tables — Manning's n by land cover, VIC defaults by soil texture, cultivar by latitude zone, crop coefficients by FAO category | YAML lookup table at `ata-kdt/constant_tables/<name>.yaml` |
| `from_basin_probe` | Basin geometry, outlet, area | run `delineate_basin.py` once |
| `from_station_search` | Observed gauges | `find_observed_station.py` |
| `from_upstream_model` | Output of an earlier model in the same coupled run | ATA coupling matrix + runtime |
| `derived` | Computed by a small rule from already-known fields | inline rule (e.g., `resolution_from_area`) |
| `default` | Sensible static fallback | hard-coded value |
| `intent_keywords` | Pick from a fixed enum based on keyword presence (e.g. routing_method: cama-flood vs lohmann) | regex match on user prompt |

## File shape

```yaml
model_id: VIC
schema_version: "1.0"
generated: "YYYY-MM-DD"
references_card: "ata-kdt/cards/VIC_ata_card.yaml"

# One entry per input the model needs. Inputs already covered by the ATA card's
# canonical_id are referenced by canonical_id; inputs that are UNNAMED in the
# card (model-specific config, file paths, etc.) are referenced by local_name.

inputs:
  # --- Forcing example ---
  - canonical_id: precipitation_rate
    strategy: from_forcing_provider
    required: true
    provider_pick:
      rule: by_location_and_period
      # logic: in_china + period<=2018 → CMFD ; else MSWX ; demo flag → NASA POWER

  # --- Dataset lookup example ---
  - input_name: soil_parameters
    strategy: from_dataset_lookup
    dataset: HWSD                          # must match data_ki/<X>/card.yaml identity.dataset_id
    args:
      lat: per_grid_cell                   # special: planner iterates over basin grid
      lon: per_grid_cell
    required: true
    fallback:
      - {strategy: from_dataset_lookup, dataset: SoilGrids}

  # --- Basin probe example ---
  - input_name: basin_shapefile
    strategy: from_basin_probe
    args:
      lat: from_user                       # planner's sub-strategy resolution chain
      lon: from_user
    required: true
    fallback:
      - {strategy: from_dataset_lookup, dataset: GRDC, args: {station_id: from_user}}

  # --- Derived example ---
  - input_name: spatial_resolution
    strategy: derived
    rule: resolution_from_area             # named rule the planner can dispatch
    inputs: [basin_area_km2]
    required: true
    # rule body: area<500 → 0.1 ; else 0.25

  # --- From user, with default ---
  - input_name: simulation_period
    strategy: from_user
    fallback:
      - {strategy: default, value: {start_year: 2000, end_year: 2010}}
    required: true

  # --- Intent keywords ---
  - input_name: routing_method
    strategy: intent_keywords
    keywords:
      cama-flood: ['flood', 'inundation', 'cama', 'hydrodynamic']
      lohmann:    ['discharge', 'routing', 'lohmann']
    fallback:
      - {strategy: default, value: lohmann}
    required: true

  # --- From upstream model (cross-model coupling) ---
  - input_name: weather_input          # for DSSAT when coupled with VIC
    strategy: from_upstream_model
    upstream_model: VIC
    upstream_output: forcing
    required: true
```

## Field reference

### Top-level keys

| Key | Required | Type | Description |
|---|:---:|---|---|
| `model_id` | ✓ | str | Must match the ATA card's `identity.model_id` |
| `schema_version` | ✓ | str | "1.0" for now |
| `generated` | ✓ | str | ISO date of file creation |
| `references_card` | ✓ | str | Relative path to the ATA card |
| `inputs` | ✓ | list | One entry per input |

### Per-input keys (common)

| Key | Required | Description |
|---|:---:|---|
| `canonical_id` OR `input_name` | ✓ | Use `canonical_id` if listed in the ATA card; else `input_name` |
| `strategy` | ✓ | One of the strategy values above |
| `required` | ✓ | true/false — drives whether the user must be asked when no fallback resolves |
| `fallback` | optional | List of alternative strategies tried in order if primary fails |

### Per-strategy required keys

| Strategy | Additional keys |
|---|---|
| `from_user` | (none) |
| `from_user_message.<kind>` | (none — kind is in the strategy name; same kinds as the `args:` sentinel form) |
| `from_forcing_provider` | `provider_pick: {rule: <rule_name>}` |
| `from_dataset_lookup` | `dataset: <dataset_id>` (must match `data_ki/<X>/card.yaml`), `args: {lat: ..., lon: ..., extra_args: ...}` |
| `from_constant_table` | `table: <table_name>` (must match `ata-kdt/constant_tables/<table_name>.yaml`), `key: <field>` (column to look up by — texture_class, latitude_zone, etc.), `args: {<key_field>: ...}` |
| `from_basin_probe` | `args: {lat: ..., lon: ...}` |
| `from_station_search` | `args: {lat: ..., lon: ..., area: ...}` |
| `from_upstream_model` | `upstream_model: <Model>`, `upstream_output: <variable_or_path>` |
| `derived` | `rule: <rule_name>`, `inputs: [list_of_dependencies]` |
| `default` | `value: <literal>` |
| `intent_keywords` | `keywords: {<value>: [keyword_list]}` |

### `from_constant_table` example

For VIC's expt/Ds/Dsmax defaults by USDA texture class:

```yaml
- input_name: vic_baseflow_params
  strategy: from_constant_table
  table: vic_defaults_by_texture
  key: usda_texture_class
  args:
    usda_texture_class: from_resolved.soil_parameters.usda_texture_class
  required: true
```

Where `ata-kdt/constant_tables/vic_defaults_by_texture.yaml` contains:

```yaml
table_id: vic_defaults_by_texture
keyed_by: usda_texture_class
source: "Maurer et al. 2002, Liang et al. 1994"
rows:
  1: {expt: 7.5, Ds: 0.001, Dsmax: 10.0, Ws: 0.95}    # clay
  9: {expt: 9.0, Ds: 0.005, Dsmax: 12.0, Ws: 0.85}    # loam
  # ...
```

### Special argument values

When an `args:` field references something the planner produces dynamically:

| Sentinel | Meaning |
|---|---|
| `from_user` | This sub-arg comes from the user (single batched question) |
| `from_user_message.<kind>` | Extract from user's free-text prompt — see kinds below |
| `from_resolved.<step>.<field>` | Pull from result of an earlier resolved input |
| `from_basin_probe.outlet.lat` | Shorthand for `from_resolved.basin_shapefile.outlet.lat` |
| `from_basin_probe.outlet.lon` | Same |
| `from_basin_probe.area` | Shorthand for `from_resolved.basin_area_km2` |
| `from_forcing_provider.path` | Pull resolved path from forcing decision |
| `per_grid_cell` | Planner iterates over basin cells (e.g. soil lookup at every cell) |

#### `from_user_message.<kind>` — sub-typed extraction

The planner runs a typed extractor against the user's message. Each kind tells
the extractor what regex / heuristic to apply:

| Kind | Extracts | Example match |
|---|---|---|
| `from_user_message.place_name` | A place / city / region name → fed to geocoder | "Bengbu", "Mekong Delta", "Yangtze upstream" |
| `from_user_message.coords` | Lat/lon string → parsed by `parse_coordinates` | "32.92, 117.36", "10°N 105°E" |
| `from_user_message.station_id` | GRDC/HYDAT station code | "GRDC 4123260", "HYDAT 08HA003" |
| `from_user_message.crop` | Crop name → matched against FAO/CROPGRIDS list | "rice", "maize", "winter wheat" |
| `from_user_message.year_range` | Two years → start/end | "2000-2010", "from 1990 to 2015" |
| `from_user_message.event` | Named event → registry lookup | "Lekima 2019", "Henan flood 2021" |

If the extractor finds nothing for a kind, the planner falls through the
`fallback:` chain. If the chain ends without resolution, the field gets added
to the "ask user" batch.

## Resolution semantics

When the planner walks the obtain map for a model:

```
for input in inputs:
    try strategy → if success, record value + provenance
    else for f in fallback (in order):
        try f → if success, record + provenance
    if all failed AND required=true:
        add to "ask user" list
    else (required=false): record as null + provenance.skipped
```

The `provenance` recorded for every resolved input becomes part of
`outputs/<run>/basin_context.yaml` so the run is fully reproducible.

## Validation

Validation is built into `derive_plan.py`: it iterates every input in the
model's ATA card and emits a strategy for each. Missing strategies surface as
`from_user` entries in the resulting plan, so the agent (or main agent's
batched ask) can collect what wasn't auto-derivable.
